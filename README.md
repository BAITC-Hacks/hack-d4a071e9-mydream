# Money Graph · HackAlem AI, трек 02 «Финансы»

Локальный MVP для AML аналитика: из транзакционной сети строит объяснимые гипотезы о роли каждого узла, группы связанных участников и очередь проверки. Исходные данные организаторов лежат в `track02/data/` и остаются на этом компьютере.

## Быстрый старт

Из папки проекта `D:\haqaton`:

```powershell
py -3 -m venv track02/.venv
track02/.venv/Scripts/python.exe -m pip install -r track02/requirements.txt
node server.mjs
```

Откройте <http://127.0.0.1:4173>. В интерфейсе нажмите **Пересчитать граф** для воспроизводимого расчёта из исходных parquet. При повторном запуске доступны ранее рассчитанные результаты. Если на Windows команда `py` недоступна, используйте установленный Python 3.11+ вместо `py -3`.

Отдельный запуск расчёта:

```powershell
track02/.venv/Scripts/python.exe track02/pipeline.py --data track02/data --out track02/out
```

Проверка:

```powershell
node --test
```

## Основной сценарий

1. Аналитик загружает локальный граф переводов и видит сводку и ранжированный список узлов.
2. Находит любой `gid` поиском или выбирает узел на направленном графе.
3. Изучает роль, приоритет, конкретные признаки, соседей и ограничения наблюдения.
4. Переходит к кластерам и выгружает три CSV для дальнейшей проверки.

Алгоритм не утверждает виновность клиента. Роли и приоритеты являются проверяемыми гипотезами, рассчитанными из предоставленной сети переводов. Особенно осторожно следует читать узлы на четвёртом колене: отсутствие исходящих переводов в обрезанном графе не доказывает, что это конечный получатель.

## Вход и выход

Входные файлы: `track02/data/nodes.parquet`, `edges.parquet`, `transactions.parquet`. Оригинальные архивы и README организаторов сохранены в `track02/materials/`, пример кода — в `track02/starter/`.

Результаты в `track02/out/`:

- `nodes_roles.csv`: `gid,role,role_score,cluster_id,priority_score,evidence`;
- `clusters.csv`: `cluster_id,n_nodes,n_seed,sum_kzt_internal,top_gids,hypothesis`;
- `top_nodes.csv`: `rank,gid,role,priority_score,why`;
- `network.json`: данные для локального интерфейса.

Сервис предоставляет `GET /api/health`, `GET /api/network`, `POST /api/rebuild`, `GET /api/export/{имя CSV}`. Он слушает только `127.0.0.1`. Ключи, облако и внешние запросы для анализа не нужны.

## Структура

- `track02/pipeline.py` — расчёт ролей, кластеров, приоритетов и экспортов.
- `server.mjs` — локальный HTTP сервер и запуск конвейера.
- `index.html`, `styles.css`, `src/app.js` — интерфейс аналитика.
- `track02/materials/` — предоставленные вводные и документы.
- `tests/` — проверки.
- `PITCH.md` — краткий сценарий демонстрации.
- `HACKATHON.md` — контрольный список готовности.

## Границы интерпретации

Наблюдаются только исходящие цепочки до четырёх колен; входящие переводы для стартовых клиентов неполны. В данных нет размеченных истинных ролей, сведений о личности клиента или внешних источников обогащения. Поэтому значения score помогают определить порядок ручной проверки, но не служат автоматическим AML решением.

Для промышленного масштаба расчёт можно вынести в пакетную обработку по разделам графа, хранить агрегаты рёбер и признаки в колонночном хранилище, а интерфейсу выдавать подграф по запросу. Логика объяснений и ограничения наблюдения должны сохраняться при таком переносе.

Проект работает локально. Сайт не опубликован. Проверенные изменения отправляются в [репозиторий команды](https://github.com/BAITC-Hacks/hack-d4a071e9-mydream) через ветку `test-arman` не реже одного раза в час.
