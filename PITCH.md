# Питч · Money Graph

## 90 секунд

«AML аналитик получает десятки подозрительных начальных клиентов, но деньги проходят через цепочку счетов. Ручной просмотр тысяч узлов не показывает, кого проверять первым.

Money Graph строит направленную сеть до четырёх колен из исходных переводов, присваивает каждому узлу объяснимую роль и приоритет и выделяет группы. Аналитик начинает с очереди, раскрывает конкретные входящие и исходящие связи, видит основание оценки и выгружает список для расследования.

Мы не объявляем людей виновными. Это гипотезы по ограниченной сети: на четвёртом колене наблюдение обрезано, а для стартовых клиентов входящая история неполна. Эти ограничения видны рядом с результатом.

За одну воспроизводимую локальную обработку три parquet файла превращаются в три готовые CSV и интерактивный граф. Необычные узлы предлагает локальная модель IsolationForest без размеченных данных; независимая проверка пробелов наблюдения снижает приоритет слабых гипотез. Следующий шаг — проверить, насколько приоритизация сокращает время ручного анализа на размеченных делах и затем масштабировать расчёт по разделам графа».

## Числа из задания

- 81 стартовый клиент;
- 2 248 узлов;
- 3 119 агрегированных направленных рёбер;
- 4 840 отдельных транзакций за июль 2026 года;
- 365 890 012 KZT оборота в наблюдаемой сети.

Эти числа описывают предоставленный набор данных; они не являются результатом оценки качества модели. Точность ролей без размеченной истины пока не измерена.

## Что показать

1. Исходные parquet и одну кнопку повторного расчёта.
2. Ранжированный список и карточку верхнего узла с evidence.
3. Направленный граф: путь денег, цвета ролей, поиск по `gid`.
4. Кластеры и CSV, которые можно передать в обычный рабочий процесс аналитика.

## Возможные вопросы

**Почему такой score?** Он составлен из наблюдаемых признаков сети, а не из скрытой метки; признаки и ограничения доступны в карточке и CSV.

**Почему это не готовое решение о блокировке?** В данных нет проверенной разметки, личности клиента и полного банковского графа. Инструмент выбирает очередность ручной проверки.

**Как масштабировать?** Хранить агрегаты и признаки в колонночном хранилище, считать компоненты и роли по пакетам, запрашивать для UI только соседство выбранного узла.
